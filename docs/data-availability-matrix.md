# Data Availability Matrix — PCOB Mode vs. Manual Mode

This document maps every field and feature in `chicken-dinner-feed` across the PCOB ingestion pipeline, internal domain models, and overlay/admin surfaces, establishing what is supported, simplified, derived, or disabled in Manual Mode.

## 1. Classification Legend

- **Fully Supported:** Can be entered directly and reliably by an operator during a live broadcast.
- **Supported with Simplification:** Represented using a simpler manual input or visual indicator that preserves honest semantics without fabricating telemetry.
- **Calculated:** Derived reliably from manually supplied values and existing configuration (roster, scoring ruleset, series history).
- **External Dependency:** Managed outside the live match loop (already operator-configured).
- **Not Practical:** Cannot reasonably be maintained manually at live broadcast pace with sufficient accuracy.
- **Needs Clarification:** Depends on an unresolved product or operational decision (tracked in [`docs/manual-mode-decisions.md`](manual-mode-decisions.md)).

## 3. Evaluation of Candidate Manual Inputs

Per Phase 2.2 of the specification, each candidate field was checked against the actual codebase:

### 3.1 Team information

- **Team name (`name`):** Already manual (`TeamRosterEditor`, 1–24 chars). Reused as-is.
- **Team abbreviation:** Does **not** exist in the codebase. [`shared/src/config/team-roster.ts#L21-L28`](../shared/src/config/team-roster.ts#L21-L28) explicitly documents that a prior version had a separate full name and short name, which was removed in `CONFIG_SCHEMA_VERSION = 3` because `TeamLogoAndColor.ini` and the overlay only ever use one `name`. **Not added.**
- **Team logo (`logoUrl`):** Already manual (`TeamLogoCell` + INI import). Reused as-is.
- **Team display order (`rank`):** Automatically calculated by `computeStandings` from total points → eliminations → team name. Never manually dragged, because the leaderboard order _is_ the point standings.
- **Team color:** Does **not** exist in the domain model or overlay (`parseTeamLogoIni` explicitly skips INI color fields, [`team-logo-ini.ts#L28-L30`](../backend/src/persistence/team-logo-ini.ts#L28-L30)). **Not added.**

### 3.2 Match information

- **Match title / round number / match timer:** None of these exist in `MatchState` or `LeaderboardOverlay`. Only `matchId` (internal key) and `phase` (`idle | live | ended`) exist. **No invented metadata fields added.**
- **Match lifecycle controls in Manual Mode:**
  - **Reset / New Manual Match:** Resets all teams' current-match `eliminations` to `0`, `aliveCount` to `4`, clears current-match elimination order and placement overrides, and assigns a fresh `matchId` so the next map can be closed into the series without colliding with the previous map's `matchId`.

## 4. Hidden Dependencies & Derived Values Analysis

1. **Alive Player Bars (`AlivePlayerBars.tsx`):**
   - _Dependency:_ Expects `team.players` to be an array of up to 4 `Player` objects with `slot: 1 | 2 | 3 | 4`, `liveState`, `health`, and `healthMax`.
   - _Crucial edge case found in code:_ In [`AlivePlayerBars.tsx#L27-L32`](../frontend/src/components/overlay/AlivePlayerBars.tsx#L27-L32), `fillFraction(undefined)` returns **`1`** (full height) with `STATE_COLOR['unknown']` (`var(--player-dead)` grey) so that an unreported PCOB team does not look wiped before the first poll arrives.
   - _Consequence for Manual Mode:_ If Manual Mode passed `players: []` or only passed `aliveCount` players, the missing slots would render as full-height grey bars! Instead, the Manual adapter **must** emit 4 `IngestPlayer` entries per present team:
     - Slots `1 .. aliveCount`: `liveState: 'alive'`, `health: 100`, `healthMax: 100` (renders full-height `var(--player-alive)` bar).
     - Slots `aliveCount + 1 .. 4`: `liveState: 'dead'`, `health: 0`, `healthMax: 100` (renders drained `deadBarHeight` track in `var(--player-dead)`).
   - _Result:_ Zero changes required in `TeamRow.tsx` or `AlivePlayerBars.tsx`, and the 4-bar indicator cleanly and honestly shows `0/4` through `4/4` alive players.

2. **Reversible Elimination Order in Manual Mode (`MatchStore.eliminationOrder`):**
   - _Dependency:_ In `MatchStore` ([`match-store.ts#L286-L306`](../backend/src/state/match-store.ts#L286-L306)), `eliminationOrder` and `eliminated` are append-only because PCOB telemetry never resurrects a completely wiped squad.
   - _Consequence for Manual Mode:_ A human operator **will** occasionally click `0` alive on the wrong team and immediately set it back to `3`. If `eliminationOrder` were strictly append-only for manual edits, that team would remain permanently locked into last place for the rest of the match!
   - _Solution:_ In Manual Mode, each team's elimination sequence is tracked with a reversible timestamp/order in the manual state store (setting `aliveCount` to `0` records `eliminatedOrder`; raising `aliveCount > 0` clears it), and passed into `IngestPlayer.rank` (or a clean reversible hook on `MatchStore`), so correcting a mistake immediately restores the team to "still playing" (`placement: null`).

3. **Guaranteed-Minimum Placement Points (`computeStandings`):**
   - _Dependency:_ While a match is live, every present team that has not yet been eliminated receives the placement points of `standingCount` (e.g. if 8 teams are left alive, all 8 are guaranteed at least 8th-place points, [`standings.ts#L160-L173`](../backend/src/scoring/standings.ts#L160-L173)).
   - _Consequence for Manual Mode:_ Because Manual Mode sets `present` (`seenTeams`) and `aliveCount` (`standingPlayerCount`), `standingCount` and guaranteed-minimum placement points work identically in Manual Mode with no special-casing.

4. **Series Banking & Deduplication (`SeriesStore.getBankedPointsForMatch`):**
   - _Dependency:_ `SeriesStore` keys closed maps by `matchId` so closing a map mid-match does not double-count points while that match remains on screen ([`series-store.ts#L160-L176`](../backend/src/state/series-store.ts#L160-L176)).
   - _Consequence for Manual Mode:_ Manual Mode must maintain a stable `matchId` (e.g. `manual-<uuid>`) for the current manual match, and generate a new `matchId` when the operator starts/resets a new manual match.
